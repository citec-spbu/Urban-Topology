# Практические задачи применения прототипа и обзор существующих решений

## 1) В каких практических задачах можно использовать прототип

Ниже перечислены прикладные сценарии, где **граф улично-дорожной сети из OSM** и **топологические метрики связности** (в т.ч. «среднее число связей/пересечений» по городу и районам) дают прямую пользу.

### 1.1. Исследовательский анализ «самоорганизация vs регулярная планировка»
**Задача:** количественно различать районы с «органически» сложившейся сетью улиц и районы с плановой (регулярной) сеткой.  
**Как помогает прототип:**
- строит граф «пересечения—ребра» и считает показатели связности;
- позволяет сравнивать **межрайонные различия** (агрегация по районам);
- даёт воспроизводимый pipeline на данных OSM.

**Выход:** набор метрик по городу и районам для сравнения морфологии:
- распределение степеней и его характеристики, включая проверку гипотез о степенном законе;
- коэффициент кластеризации и средняя длина пути как показатели локальной связности и «компактности» сети;
- центральности для выявления структурных различий между районами.

---

### 1.2. Сравнение районов внутри города и межгородские сравнения
**Задача:** сопоставлять топологию сети разных районов (или разных городов) для урбанистических исследований, исторической географии, анализа морфологии.  
**Как помогает прототип:**
- единая методика на одном источнике (OSM);
- интерактивная визуализация графа + метрик;
- экспорт результатов в CSV для статей и отчётов.

---

### 1.3. Быстрый «скрининг» связности территории перед углублённым моделированием
**Задача:** понять, стоит ли и как глубоко запускать сложные модели (транспортные, агентные), оценив структуру сети «в первом приближении».  
**Как помогает прототип:**
- быстро даёт интегральные показатели по районам;
- подсвечивает «аномальные» зоны: низкая связность, доминирование тупиков, разрывы сети.

---

### 1.4. Выявление «узких мест» и ключевых пересечений
**Задача:** найти элементы уличной сети, отказ/перегрузка которых сильнее всего влияет на связанность и маршрутизацию.

**Как помогает прототип (с учётом текущих скриптов):**
- позволяет выделять узлы (пересечения) с высокой промежуточной центральностью — потенциальные критические точки сети.
- визуализация центральности помогает интерпретировать результаты на карте/графе и сравнивать районы.
  
---

### 1.5. Сопоставление топологии с социально-экономическими/экологическими данными
**Задача:** проверять гипотезы типа «связность уличной сети коррелирует с плотностью услуг, пешеходной активностью, безопасностью, доступностью остановок».  
**Как помогает прототип:**
- выдаёт районные показатели, которые легко соединяются с данными по районам (статистика, POI, аварийность и т.п.);
- обеспечивает воспроизводимую методику расчёта на открытых данных.
- показатели доступности/центральности можно использовать как прокси «сетевой доступности» района и сопоставлять с плотностью услуг, остановок, показателями мобильности;
- выделять узлы, “встроенные” в важные части сети (важность через связи с важными узлами), что полезно для морфологического сравнения районов.


---

### 1.6. Образовательные и демонстрационные кейсы
**Задача:** учебные проекты по GIS/графам/урбанистике: «как из OSM получить граф и посчитать метрики».  
**Как помогает прототип:**
- веб-интерфейс снижает порог входа;
- визуализация помогает объяснять графовые концепции.

---

## 1.7. Уже реализованные аналитические метрики и скрипты в проекте

В проекте уже подготовлены скрипты/ноутбуки для расчёта ключевых графовых показателей на основе NetworkX (применимо к графу уличной сети после построения из OSM):

- `betweenness.ipynb` — промежуточная центральность (betweenness), полезна для поиска «узких мест» и узлов/пересечений, через которые проходит много кратчайших путей.
- `centrality.ipynb` — средняя длина пути и коэффициент кластеризации; показатели «глобальной связности» и локальной связности/«сетчатости» структуры.
- `degrees.ipynb` — анализ распределения степеней (в т.ч. проверка степенного закона); применимо для диагностики самоорганизующихся структур и сравнения морфологии районов.
- `metrics.ipynb` — расчёт набора центральностей: degree / eigenvector / closeness / betweenness + визуализация значений на графе.
- `bgraph_threshold.py`, `buildinggraph_kneig.py` — скрипты построения/предобработки графа (пороговые правила/окрестности k-neighborhood; используются для формирования аналитического графа перед расчётом метрик).

Важно: часть метрик может быть реализована на уровне ноутбуков (офлайн-расчёт). Для превращения в «продуктовый» инструмент требуется интеграция этих расчётов в backend веб-приложения и единый формат экспорта результатов по городу/районам.

## 2) Анализ существующих решений под эти задачи

Ниже — обзор наиболее близких инструментов/платформ и то, как они закрывают указанные сценарии.

### 2.1. Библиотеки для построения уличных графов и расчёта метрик (кодовые решения)

#### OSMnx (Python)
- **Что это:** де-факто стандарт для извлечения уличных графов из OSM, интегрируется с NetworkX.  
- **Сильные стороны:** мощная загрузка/очистка данных, широкий набор сетевых метрик, маршрутизация, визуализации.  
- **Слабые стороны относительно прототипа:** требует Python-окружения; нет «из коробки» удобного веб-интерфейса для исследователей без навыков программирования; районная агрегация зависит от внешних границ/пайплайна.
- [OSMnx documentation](https://osmnx.readthedocs.io/)

#### NetworkX (Python/R)
- **Что это:** универсальные библиотеки графового анализа.  
- **Сильные стороны:** очень широкий набор алгоритмов и метрик.  
- **Слабые стороны:** сами по себе не решают извлечение уличной сети из OSM и не дают UI/картографию.
- [NetworkX documentation](https://networkx.org/)

---

### 2.2. GIS-инструменты

#### QGIS
- **Что это:** популярная open-source GIS-платформа.  
- **Сильные стороны:** визуализация, пространственный анализ, работа с районами/границами, можно подтянуть OSM.  
- **Слабые стороны:** топологический графовый анализ требует дополнительных модулей/скриптов; воспроизводимость зависит от настроек; веб-доступ «из коробки» отсутствует (нужны QGIS Server/публикация).
- [QGIS web site](https://qgis.org/)

#### ArcGIS
- **Что это:** промышленный GIS стек.  
- **Сильные стороны:** мощные инструменты сетевого анализа, готовые workflow для организаций.  
- **Слабые стороны:** коммерческая лицензия; часто ориентирован на транспорт/маршрутизацию, а не на исследовательскую топологию «самоорганизация vs регулярность»; интеграция с OSM возможна, но не всегда тривиальна.
- [Esri web site](https://www.esri.com/en-us/home)

---

### 2.3. Space Syntax

#### depthmapX
- **Что это:** инструмент space syntax (интеграция, выбор, видимость и т.п.).  
- **Сильные стороны:** сильная методология для исследований городской морфологии, востребован в академической среде.  
- **Слабые стороны:** своя парадигма графа/сегментов; работа с OSM возможна, но требует подготовки данных; веб-интерфейса нет; районная агрегация — вручную/через GIS.
- [Space Syntax Toolkit for QGIS repository](https://github.com/SpaceGroupUCL/qgisSpaceSyntaxToolkit)
- [depthmapX - multi-platform spatial network analyses software repository](https://github.com/SpaceGroupUCL/depthmapX)

#### sDNA
- **Что это:** набор инструментов (часто как расширение для GIS) для сетевого анализа, близко к space syntax.  
- **Сильные стороны:** продвинутые показатели, применимость в планировании.  
- **Слабые стороны:** порог входа, установка/лицензирование (есть разные варианты), не «лёгкий» веб.

---

### 2.4. Веб-инструменты визуализации OSM и картографические платформы

#### kepler.gl
- **Что это:** веб-визуализация геоданных.  
- **Сильные стороны:** очень сильная визуализация, фильтры, слои.  
- **Слабые стороны:** не дают готового построения *топологического графа улиц и расчёта графовых метрик; требуют подготовки данных отдельно.
- [kepler.gl web site](https://kepler.gl/)

#### overpass turbo
- **Что это:** веб-интерфейс запросов к OSM через Overpass API.  
- **Сильные стороны:** быстро достать данные.  
- **Слабые стороны:** нет графовых метрик; это скорее «выгрузка», а не анализ.
- [overpass turbo web site](https://overpass-turbo.eu/)

## 3) Ниша прототипа

### 3.1. Ключевое отличие
Большинство сильных инструментов либо:
- **кодовые** (OSMnx/NetworkX) — мощно, но нужен программист/среда,  
либо
- **десктопные GIS** — гибко, но сложнее воспроизвести и поделиться,  
либо
- **веб-визуализация без метрик** (kepler.gl),  

**Прототип закрывает именно “web-first” исследовательский сценарий:** загрузка города → построение графа → визуализация → расчёт метрик.
При этом значимая часть аналитики уже реализована в виде ноутбуков/скриптов и может быть перенесена в backend веб-приложения для автоматического расчёта по городу и районам.

---

## 4) Рекомендации по усилению прототипа под практические задачи

Так как ключевые метрики уже реализованы, основной следующий шаг — продуктовая интеграция:

- перенести расчёты в backend-пайплайн (или оформить как сервис/таски), чтобы метрики считались автоматически для выбранного города/района;
- параметризовать фильтрацию OSM и явно фиксировать эти правила в отчёте;
- для корректности пересечений учитывать мосты/тоннели/слои, чтобы не считать разные уровни как пересечения;
- добавить «паспорт района»: сводка (avg degree, clustering, avg shortest path length, доля degree=1, топ-узлы по betweenness/closeness).
